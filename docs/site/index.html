What an owner should feel

When the phone rings after hours, the job should not vanish into voicemail. The office should wake up to a usable lead: who called, where they are, what broke, how urgent it is, and when they want someone there — already sitting in the CRM.

That feeling is the product. Retell, n8n, and GHL are how you get there.

Architecture

Caller
  → Retell voice agent (prompt + tool timing)
  → POST create_service_request (flat JSON)
  → n8n webhook (validate fields)
  → optional GoHighLevel contact + opportunity
  → JSON status back to Retell
  → agent speaks only confirmed result

Colloquial summary

Maya answers for Princeton Heating & Air. She asks one question at a time, reads the details back, then sends a service request only after the caller confirms. If the backend says the request landed, she shares the confirmation. If something is missing or the tool fails, she routes to a human instead of bluffing.

CollectName, phone, ZIP/address, issue, urgency, new/existing, preferred window.
ConfirmRead-back before any CRM write or “we got it” promise.
Hand offStructured JSON into automation, then toward GHL.
Stay honestNo fake quotes, arrival times, or success on failed tools.

Technical summary

Prompt sections

Role, speaking style, safety rules, intake sequence, tool timing, response handling. Each section exists to stop a different failure mode.

Webhook contract

Required flat fields: caller_name, phone, address_or_zip, service_type, issue_summary, urgency, preferred_window, existing_customer.

n8n

Importable workflow: Webhook → Validate Request (Code) → Respond to Webhook. Success returns status: received; incomplete data returns status: needs_human.

GoHighLevel

Documented next hop after validation: upsert contact by phone, create opportunity on an inbound pipeline, optional SMS, return a searchable confirmation reference. See the GHL wiring note in the repo.
